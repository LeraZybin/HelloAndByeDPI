# HelloAndByeDPI — 0.6.1

Нативный интерфейс на русском и английском для локального SOCKS5-прокси ByeDPI.
По умолчанию приложение автоматически включает системный прокси после запуска
движка и восстанавливает прежние настройки при отключении. Браузеры и другие
программы, использующие системные настройки прокси, подключаются автоматически.
На Windows x64 также доступен VPN-режим для IPv4-трафика всех приложений.

## Простой интерфейс

По умолчанию открывается минималистичная версия: крупная кнопка «Включить»,
текущая стратегия, избранные, каталог всех 60 стратегий с параметрами,
кнопка ручного ввода и «Тест стратегий».
Переключатель режима выбирает системный прокси или VPN. Изменять параметры,
порт и ручной режим можно в полной версии. Выбранная после теста стратегия
сохраняется и добавляется в избранное; свои параметры можно добавить кнопкой
«В избранное» в полной версии. Для запуска выбранной стратегии нажмите «Включить».

В простом тестере нажмите «Начать тест». Используются последние выбранные
списки сайтов (при первом запуске — YouTube) и совместимые стратегии.
Настроить списки, таймаут и попытки можно через «Полная версия».
Результаты сортируются по доступности по убыванию прямо во время проверки.
Клик по завершённой стратегии применяет её; если тест ещё идёт, сначала
останавливается тестовый движок. В полной версии выбор строки показывает
подробности, а применение выполняется отдельной кнопкой.

На обоих экранах сверху расположены выбор языка «Русский / English» и кнопка
«Полная версия / Простая версия». Язык сохраняется между запусками.
Иконка с золотыми крылатыми носками включена в macOS- и Windows-ресурсы.
Служебное имя хранилища оставлено прежним для восстановления сети и настроек
после обновления с ByeDPI Desktop.

## Возможности

- Запуск и остановка встроенного движка; завершение движка при обычном закрытии окна.
- Локальный адрес `127.0.0.1`, выбор порта, копирование адреса.
- Редактирование и сохранение строки параметров, импорт из UTF-8 `.txt`.
- Начальные варианты TCP/TLS-разделения и режим без обхода для диагностики.
- Ограниченный по размеру журнал и проверка доступности порта после запуска.
- Проверка параметров; запуск через массив аргументов, без командной оболочки.
- Автоматическая настройка системного прокси, включённая по умолчанию.
- VPN-режим Windows x64 через tun2socks и подписанный драйвер Wintun.
- Восстановление прежних настроек до остановки движка, при его сбое и при закрытии окна.
- Резервная копия для восстановления после аварийного завершения, кнопка «Восстановить сеть».
- Тест 60 политик на выбранных списках сайтов, подробные результаты и экспорт CSV.

Пресеты не гарантируют обход у конкретного провайдера.
Статус «Подключено» подтверждает запуск и настройку прокси, а не доступ
к заблокированному сайту. Автоматического подбора стратегий пока нет.

## Тест политик

В главном окне нажмите «Тест стратегий».
Кнопка доступна при отключённом основном прокси. Тестер использует отдельный
локальный порт и не меняет системные настройки сети.

В полной версии доступны дополнительные настройки:

1. Выберите политики: предустановлены все 60 строк из
   [romanvht/ByeByeDPI](https://github.com/romanvht/ByeByeDPI), без изменения параметров.
   По умолчанию отмечены совместимые с текущей ОС. В этой версии проверку ключей
   проходят 23 политики на macOS и 53 на Windows. Это не гарантия успешного обхода.
   Linux-параметры `--md5sig`/`--drop-sack` недоступны на обеих настольных платформах;
   `--fake`, `--fake-sni`, `--timeout` также недоступны на macOS.
   Несовместимые политики остаются в списке с объяснением; при выборе пропускаются.
2. Отметьте один или несколько списков: общий (6), YouTube (13), Googlevideo (19),
   Discord (21), Telegram (52), соцсети (16), Cloudflare (4), Турция (8).
   Можно добавить свои адреса или импортировать `.txt`/`.sites` — по одному адресу
   на строку. Адрес без схемы получает `https://`. Повторы удаляются; строки с `#`
   считаются комментариями. Поддерживаются только HTTP/HTTPS, без логина и пароля в URL.
3. Задайте таймаут (1–60 секунд), число попыток (1–5), параллельность (1–12).
   SNI заменяет `{sni}` в исходных политиках; по умолчанию `ya.ru`.
4. Нажмите «Начать тест». Сначала проверяются прямой доступ и прокси без обхода,
   затем выбранные политики. Прогресс и результаты появляются во время работы.
5. Выберите строку результата: ниже появятся сайты, успехи по попыткам, HTTP-коды,
   время ответа и ошибки. Во время проверки политики сортируются по числу доступных
   сайтов, затем по медиане времени успешных запросов.
6. «Применить выбранную» переносит параметры в главное окно и сохраняет их.
   Для подключения нажмите «Включить». «Экспорт CSV» сохраняет отдельные попытки,
   параметры, время запуска и результаты. При остановке доступны частичные результаты.

Списки и настройки тестирования сохраняются; таблица результатов живёт до закрытия
диалога или нового теста. Для истории используйте экспорт CSV.

«Доступно» означает HTTP 2xx/3xx хотя бы в одной попытке. «Ответ есть» включает
полученные HTTP-ошибки (например, 403/404): они показаны отдельно и не считаются
успешным доступом. По нескольким попыткам видно, какие сайты работают нестабильно.
Медиана вычисляется только по успешным попыткам, а не по быстрым отказам.
Тестер выполняет GET, следует не более чем пяти перенаправлениям и читает до 64 КБ
ответа. Это проверка доступности URL и начальной части ответа, а не воспроизведения
видео, работы всего сайта или отсутствия страницы-заглушки. TLS-сертификаты проверяются.
Сертификат с ошибкой, обрыв до заявленного размера (в пределах лимита) и таймаут
не считаются успешным доступом. При повторных попытках используются новые соединения.
DNS в тестах через прокси передаётся SOCKS5-серверу; прямой контрольный замер идёт напрямую.

Исходные списки находятся в `data/byebyedpi`, закреплены на commit
`96a3c1ff555043d915af814aa4f0e9a572c89aba`. Их лицензия GPL-3.0 и указание источника
включены в эту папку и в сборки. Код настольного тестера написан отдельно.

## Запуск на Mac

Для MacBook Air Intel 2013 предназначена сборка
`build-intel/HelloAndByeDPI.app` (в архиве `dist/HelloAndByeDPI-macos-intel.zip`).
Распакуйте приложение, запустите его и нажмите «Включить».
Опция «Автоматически настраивать системный прокси» уже включена.
macOS может показать стандартный запрос разрешения администратора для изменения сети.
После подключения Safari и браузеры, использующие системные настройки, получают
адрес прокси автоматически. Вводить адрес и порт в браузере не нужно.
При нажатии «Отключить» или закрытии окна прежние настройки возвращаются.

Если в браузере раньше был вручную указан прокси либо выбран режим без прокси,
он может игнорировать системные настройки. В таком случае выберите в нём
«Использовать системные настройки прокси». Приложения, вообще не поддерживающие
системный прокси, автоматически перенаправляться не будут.

Для ручного режима снимите опцию автонастройки. Адрес для клиента:
SOCKS5, `127.0.0.1`, порт `1080` (или выбранный в окне).
После остановки в ручном режиме прокси в клиенте нужно отключать самостоятельно.

## Как работает автоматическая настройка

На macOS используется SystemConfiguration: включается SOCKS для доступных
включённых служб текущего сетевого расположения, временно отключаются HTTP/HTTPS
прокси и автоматическая конфигурация PAC/WPAD. Прежние значения сохраняются
до изменений. Поэтому переключение между уже существующими Wi-Fi и Ethernet
в этом расположении учитывается; добавление новой службы или смена расположения
требует переподключения в приложении. Исключения прокси остаются прежними.

На Windows используется WinINET для текущего пользователя, стандартного LAN-соединения:
`http=127.0.0.1:порт;https=127.0.0.1:порт`. Браузер передаёт HTTPS через HTTP
CONNECT, а ByeDPI принимает HTTP и SOCKS5 на одном локальном порту.
Автоопределение и PAC временно отключаются флагами;
их адреса и список исключений не перезаписываются. При восстановлении возвращаются
исходные сервер и флаги. Это не настройка WinHTTP-служб или отдельных RAS/VPN-соединений.
Для ручной настройки и VPN движок на том же порту принимает SOCKS5.
Windows-реализация требует проверки на настоящей Windows.

VPN-режим запускает tun2socks через локальный SOCKS5 ByeDPI, создаёт адаптер
HelloAndByeDPI и добавляет два активных IPv4-маршрута `0.0.0.0/1` и
`128.0.0.0/1`. Исходящие соединения ByeDPI привязываются к адресу физического
интерфейса, чтобы не попадать обратно в туннель. Для адаптера используется DNS
`1.1.1.1`. Создание адаптера и маршрутов требует подтверждения UAC. При обычном
отключении маршруты удаляются до остановки tun2socks и ByeDPI.

Резервная копия `proxy-recovery.ini` лежит в папке данных приложения.
При следующем запуске после сбоя приложение пробует восстановить сеть.
Если ОС отказывает в восстановлении, копия сохраняется и становится доступна
кнопка «Восстановить сеть». При обычном отключении движок продолжает работать,
пока восстановление не удалось, чтобы не оставлять настройки на неработающем порту.
При принудительном завершении процесса или отключении питания восстановление
не мгновенное: нужно снова запустить приложение. Если движок остался сиротским
процессом и занимает порт, завершите его или выберите другой порт после восстановления.
Изменённый пользователем адрес другого прокси не перезаписывается восстановлением.

Для переноса с Android вставьте именно строку параметров (без имени исполняемого
файла). Короткие ключи, например `-s1`, поддерживаются. Импорт `.txt` содержит
одну стратегию, а не список профилей или JSON-конфигурацию Android.
Адрес/порт задаются интерфейсом. Кавычки группируют значения с пробелами;
обратные косые черты сохраняются буквально. Команды оболочки не исполняются.
Часть редких ключей движка не входит в разрешённый набор интерфейса.

На macOS данная версия движка не поддерживает `--fake`, `--fake-sni`,
`--timeout`: они отклоняются до запуска. У `--disorder` и других методов
эффект зависит от сетевого стека ОС. Файлы, указанные в параметрах,
лучше задавать абсолютными путями.

## Совместимость и статус проверки

| Платформа | Цель | Проверка |
|---|---|---|
| Windows 8/8.1, 10, 11 | x64, MinGW, WinAPI baseline 0x0602 | В 0.6.1 настройка IPv4 VPN вынесена из GUI-потока; требуется проверка за реальным DPI |
| macOS Intel | 10.13+; MacBook Air 2013 с обновлённой ОС | x86_64-сборка и GUI lifecycle-тест через Rosetta пройдены; физический Air и macOS 10.13 ещё не проверены |
| macOS Apple Silicon | 11+ | Сборка, SOCKS5-тест, GUI lifecycle и включение/восстановление настоящего системного прокси пройдены на текущем Mac |

Год Mac не определяет установленную версию ОС. Если на Air стоит macOS
старше 10.13, эта сборка для него не предназначена.
Совместимость старых ОС требует проверки готовых бинарников на этих ОС;
установка deployment target сама по себе её не доказывает.
Сборки не подписаны сертификатом Developer ID и не нотарифицированы.

## Сборка

Зависимости закреплены: wxWidgets 3.2.6, ByeDPI commit
`ba532298de7b28cfe854aea83d061369d13ca290`, tun2socks 2.5.2 и Wintun 0.14.1.
Для HTTPS-тестов macOS использует системную libcurl. На Windows скрипт также
скачивает curl 8.17.0 с проверкой SHA-256; он собирается статически с Schannel
и системным хранилищем сертификатов. Системный `curl.exe` не требуется.
Скрипт проверяет SHA-256 скачанных архивов. Уже существующие каталоги
`third_party` используются как есть; для повторного получения чистых исходников
переместите их в резервную папку и повторите загрузку.

Требуются Python 3.8+, CMake 3.20+ и компилятор C/C++.

```sh
python3 scripts/fetch_dependencies.py
cmake -S . -B build-intel -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=x86_64 -DCMAKE_OSX_DEPLOYMENT_TARGET=10.13
cmake --build build-intel -j 4
```

Для Apple Silicon замените архитектуру на `arm64`, minimum target на `11.0`
и каталог сборки на `build`. Для Windows используйте MSYS2 MINGW64 или MINGW32,
соответствующие GCC/CMake/Ninja/Python, затем:

```sh
python scripts/fetch_dependencies.py
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
```

MSVC не поддерживается этой конфигурацией движка. Windows-пакет должен содержать
`HelloAndByeDPI.exe`, `ciadpi.exe` и каталоги `lib`, `licenses`, `data` рядом друг с другом.
Основное приложение, tun2socks, Wintun и runtime DLL находятся в `lib`; небольшой
загрузчик в корне позволяет Windows найти их ещё до запуска основного приложения.
Автоматическая сборка описана в `.github/workflows/build.yml`; она ещё не запускалась.

## Проверки

```sh
ctest --test-dir build --output-on-failure
python3 tests/proxy_smoke.py build/ciadpi
build/HelloAndByeDPI.app/Contents/MacOS/HelloAndByeDPI --smoke-test
python3 tests/probe_integration.py build/ciadpi build/probe_integration
build/HelloAndByeDPI.app/Contents/MacOS/HelloAndByeDPI --ui-smoke-test
# Дополнительно проверить GUI тестера в графической сессии:
python3 tests/probe_integration.py build/ciadpi build/probe_integration build/HelloAndByeDPI.app/Contents/MacOS/HelloAndByeDPI
```

CTest проверяет параметры, откат при ошибках, сохранение резервной копии,
восстановление после перезапуска и объединение настроек macOS с пользовательскими
изменениями. Он не меняет системную сеть. Второй тест выполняет SOCKS5
handshake и HTTP-обмен с локальным сервером через настоящий движок с TCP-разделением.
Третий открывает окно, запускает движок на порту 19581, ждёт доступности порта,
останавливает процесс и закрывает окно. Ему нужна графическая сессия.
Эти тесты не проверяют реальный обход DPI. Обычный GUI-тест не изменяет пользовательские параметры или системную сеть.

Отдельная интеграционная проверка `--system-proxy-smoke-test` действительно
включает системный прокси на локальном порту 19581 и затем восстанавливает его.
На macOS требуется подтверждение администратора. Эта проверка выполнена на текущем
Mac: приложение завершилось с кодом 0, действующие системные настройки до и после
теста (`scutil --proxy`) совпали. Старый Intel Mac и Windows 8 пока не проверены.

`probe_integration.py` поднимает локальные HTTP/HTTPS-серверы и проверяет реальные
запросы напрямую и через ByeDPI: 200, 403/404, редирект, лимит 64 КБ, обрыв, таймаут,
недоверенный TLS-сертификат и отмену активных запросов. Переменные окружения прокси
не должны влиять на выбранный маршрут. Опциональный GUI-тест проверяет контрольные
замеры, исходную политику №60, оба языка и режима интерфейса, сортировку во время
проверки и применение результата, в том числе до завершения тестирования. Эти проверки пройдены на
текущем Mac; внешние сайты не запрашивались. Для тестового сертификата нужен `openssl`.
